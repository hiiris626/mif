# GT来源与DAPI单一筛选规则的复核

日期：2026-09-25。已有掩膜来自上游处理数据，包含核外扩张；两种Dice预览均只作历史诊断。最新决定直接使用MIPHEI已质控发布patch，停止二次StarDist扫描；不再等待清洗口径选择。下文保留来源和筛选偏差分析，不作为当前主流程。

## 1. 已有掩膜来自哪里

本地实际读取的是 `/data/weiyh/orioncrc_miphei/ORIONCRC_dataset_tile_20x/nuclei/` 下的整数标签TIFF，通过每个split CSV的 `nuclei_path` 找到对应patch，不是此次H&E StarDist生成的结果。

项目 `PLAN.md` 的数据来源记录指向MIPHEI处理版：[Zenodo 15340874](https://zenodo.org/records/15340874)，文件 `ORIONCRC_dataset_tile_20x.zip`。作者预处理文档说明在DAPI上做Cellpose，再做核扩张；论文§3.4.4明确写出：使用微调的Cellpose分割DAPI，向外扩张2μm作为细胞区域近似。[作者预处理说明](https://github.com/Sanofi-Public/MIPHEI-ViT/blob/main/preprocessings/README.md)、[作者论文](https://arxiv.org/html/2505.10294v1#S3.SS4.SSS4)

本地抽查TIFF形状333×333、int32，继承的OME元数据通道名为 `cell`、`boundary`，进一步支持其为扩张细胞区域标签。patch文件实际仅有一张标签图；元数据继承WSI的尺寸/通道信息，不能把其中WSI尺寸当作patch尺寸。路径、元数据和来源链接已保存到 `qc_reference_preview/mask_provenance.json`。

因此需纠正先前“已有核GT”的称呼：它是**算法生成的、核扩张后的细胞区域代理**，不是人工纯核GT。未取得当时生成run的完整参数和原始未扩张核文件，因此也不能承诺用腐蚀2μm就精确恢复原核；扩张中的碰撞、裁剪、下采样不可简单逆转。

## 2. 为什么现有Dice筛选有问题

- **比较对象不同**：H&E StarDist输出核；已有掩膜是核外扩张后的细胞代理。即使位置完全正确，面积差异仍会压低Dice。理想同心圆，核半径2μm、外扩2μm时，核与细胞区域Dice为 `2×2²/(2²+4²)=0.4`，达不到0.6金标，不能据此说配准不好。
- **强度>0不等于核轮廓**：另一种GT是处理后Hoechst>0的前景，它受去背景、归一化、残余弱信号影响，不是独立分割标注。
- **StarDist漏检也会降低Dice**：低Dice混合了HE分割误差、GT分割误差、掩膜定义差异和配准误差，不能把它直接解释为“整张patch无效”。
- **倾向保留核多、核清晰的区域**：可能减少低核密度区域及核外结构相关marker的训练覆盖。是否形成偏差，需要比较筛选前后各病例、marker、核密度和组织区域分布。
- **金标只是一致性等级**：两个算法掩膜一致不证明16个通道标签都正确，更不是人工金标准。

原作者本身采用伪影、H&E质量和配准等多项检查，并非仅用一个核Dice阈值筛所有任务数据。[论文§3.4.2](https://arxiv.org/html/2505.10294v1#S3.SS4.SSS2)

## 3. 会不会丢掉没有DAPI但其他通道有信号的样本

会。当前 `binary_dice` 把双空也记0；因此DAPI全零的patch不可能通过Dice≥0.2，即使其他通道有信号也会被剔除。这是规则本身的结果。

还存在一个**直接的条件冲突**：如果Hoechst也要做patch级true:false=1:1，同时又要求只有DAPI/Hoechst Dice≥0.2才能入选，那么Hoechst=false的patch已在第一步全部被筛掉，后续不可能平衡。当前平衡脚本遇到空组会报告不可行，而不会复制/伪造阴性样本。

需区分三件事：

| 情况 | 含义 | 应对 |
|---|---|---|
| 通道未采集、损坏或染色失败 | 标签未知，不是生物学阴性 | 该通道标为不可监督，不能作为false；其他有效通道可另行保留 |
| 通道存在但整个patch为0 | 可能无核、弱信号被处理清零，也可能质量问题 | 核Dice标为不可评价，结合HE与其他通道核查，不能自动证明好或坏 |
| patch中部分像素DAPI=0、其他marker>0 | 核外表达或非核区域，不等于背景 | 不用DAPI核mask裁掉其他marker监督 |

本地通道名为Hoechst；“DAPI”在此前讨论中指核染色通道。当前读取器要求固定通道结构，不能把“数组全0”叫作“没有采集这个通道”。

## 4. 实测证据与边界

对41个病例各随机抽100张，共4100张，种子42；这是病例分层抽样，不是全量，也不是按patch等概率抽样：

- **3张**Hoechst整通道全零，但HE组织内其他通道有非零值。
- **4038张**存在Hoechst=0、其他通道>0的局部像素。
- 原82张双GT预览中，强度口径会剔除41张、扩张细胞口径37张；这些被剔除的patch都还有其他通道非零信号。这不证明全部应保留，但说明Dice淘汰会影响其他任务监督。

| patch_id / 病例 | HE组织像素 | 其他通道非零像素 | 其他通道最大值（组织内，0–255） |
|---|---:|---:|---:|
| 250993 / CRC03 | 5816 | 290 | 62 |
| 61061 / CRC04 | 5550 | 110 | 70 |
| 232595 / CRC38 | 2273 | 59 | 33 |

三张图都只有少量组织区域与零星信号；非零不等于经过验证的生物学阳性，不能据此宣称“找到了3张优质漏删样本”。它们证明这种数据组合确实存在，应进入复核分支。样本清单、信号强度和图见 `qc_bias_audit_4100/`。

全318450张的HE/IF/掩膜文件名坐标后缀一致，没有发现文件名级错配；这不证明像素级配准无偏移，不能替代图像核查。结果见 `qc_reference_preview/coordinate_audit.json`。

## 5. 建议修改筛选的组织方式（方案，尚未启用）

1. **先判断数据和通道是否可用**：读图、通道身份、配对、组织、染色/伪影。通道缺失与真阴性分开。
2. **仅在核染色可评价的patch上做核一致性QC**：取得未扩张DAPI核分割，或在DAPI上重新跑荧光核模型；HE与DAPI比较同一种“核”定义。分割模型需抽样校准，不能把两模型的共同错误当作GT。
3. **核QC不可评价的样本走单独分支**：DAPI全零、核太少或疑似分割失败且其他marker有信号时，标为待复核，原始数据保留；复核通过后可用于有效通道监督。不能直接放入金标，也不能一律丢弃。
4. **低Dice作为核查信号**：先区分明显配准失败与分割/面积定义差异。0.2/0.6暂保留为待验证候选阈值，不作为全量自动淘汰的已定口径。可辅助检查核中心/密度对应和HE–IF组织覆盖，避免边界扩张主导判断。
5. **按通道保留有效监督与独立采样**：缺失通道的loss/指标置为ignore；不是整个patch删除。false样本必须是该通道已观测且可信的阴性。背景由HE组织和所有有效通道联合定义，不能由DAPI一个通道定义。
6. **报告分布变化**：每病例/通道报告筛前筛后true/false数量、核稀少样本保留率及待复核数量，再确定是否允许清洗。

这会增加“QC不可评价/待复核”状态，与原先仅三类的设计不同，所以当前仅提出方案并保存诊断证据，没有擅自将它混入三类全量统计或启动训练。
