## 1. 结论

**存在确定的运行错误和逻辑问题，当前目录不能直接当作三个可独立复现的历史版本。**

- 三版共有的 **11 个 Python 文件逐字节相同**，全部是后期代码副本；版本区别主要保存在实际 checkpoint 配置、权重结构、启动脚本、日志和结果中。
- 三版独立运行训练入口都会缺少 `datacore.training_monitor`；编码器还缺少版本目录内的 `configs/virchow2_config.json`。
- v1/v2 启动脚本会调用项目根目录的新代码，并继承 v3 的 log 归一化、前景加权及后加的早停默认设置。
- 当前架构不能加载实际 v1 checkpoint；README 给出的“近似 v1 参数”也不能还原 v1。
- 验证样本计数、评估预测完整性、可视化文件名、最佳权重选择及旧 checkpoint 续训等存在问题，详见下一节。

本次新增审查报告、复核脚本和证据文件。原有训练、推理和评估源码未改动，未启动训练或覆盖历史产物。

## 2. 已确认问题及修复方向

下述 `code/...` 指三版共有源码；三份内容相同。P1 表示阻断运行或明显跑错实验，P2 表示特定流程错误、指标或复现受影响。

### F01 / P1：三个版本均未收齐必要依赖和配置

- 位置：`code/vit_matte/train.py:48`；`code/vit_matte/encoder.py:27,58`。
- 三个 `code/datacore/` 都没有 `training_monitor.py`。分别进入三个 `code/` 执行 `python -B -m vit_matte.train --help`，均复现 `ModuleNotFoundError: No module named 'datacore.training_monitor'`。
- `encoder.py` 按自身位置寻找 `code/configs/virchow2_config.json`，三版均不存在。单独调用 `_build` 已复现 `FileNotFoundError`，发生在创建模型之前。
- 必要文件实际位于项目根目录。仅复制 Python 主文件没有形成完整运行目录。
- 共享重评脚本还调用未收录的 `eval.metrics_gpu`、`scripts.plot_all_results`；共享可视化脚本搬迁后插入的是 `_shared` 路径，那里没有其所需的顶层包。给它补项目根路径会转而调用根目录代码，仍无法保证运行的是归档副本。
- 修复：补齐明确版本的依赖、模型配置、环境说明，统一正确的包路径。不能仅以“语法检查通过”判断可运行。

### F02 / P1：启动脚本运行位置、默认参数和版本名不一致

- 位置：v1 `code/launch/auto_start_vit512.sh:18–24`；v2 `code/launch/auto_start_vit_v2.sh:20–35`；v3 三个 launch 脚本。
- 五个正式版本启动脚本都 `cd /home/weiyh/h2e_mif_benchmark`，因此执行根目录 `vit_matte`，不会使用本版本的 `code/vit_matte`。
- v1 只传名字、GPU、epoch、batch。当前默认会变成 ViT-448、四层特征、多尺度卷积、log 目标、fg=10，与历史 v1 不同。
- v2 明确传入了结构参数，但没有 `--no-log_norm --fg_weight 0`，当前会以 v2 名义训练 log+前景加权模型。
- 当前训练默认增加早停 `patience=8/min_delta=0.02/warmup=3`，三个历史 checkpoint 均没有这些配置。现有脚本没有显式冻结这一行为，不能承诺重跑满历史 15 epoch。
- 修复：先解决 F01，再把脚本入口绑定到版本目录，显式保存全部实验参数。v2 至少需要关闭 log 和前景加权；v1 还必须先解决 F03。历史复现是否关闭早停需明确写入配置。

### F03 / P1：当前“兼容 v1”的架构与采样声明不成立

- 位置：`code/vit_matte/vitmatte_unet.py:156–168`；`code/vit_matte/sample.py:51–68`；共享 `wsi_panorama.py:150–155`。
- 实际 v1 checkpoint 包含 `vit_proj.weight: [512,1280,1,1]` 和 `conv16.block.0.weight: [512,1024,3,3]`。
- 当前构造器始终创建 `ViTNeck` 和 `MultiScaleConv` 的 `conv16`；`--no_multi_scale` 只关闭 DetailCapture 的 c1/c2，并不会关闭 conv16 多尺度分支。
- README 的 `--vit_layers 32 --no_multi_scale --vit_size 224` 构造出约 **23.451M** 可训练参数，历史 v1 日志为 **13.421M**，结构不是同一个模型。
- v1 checkpoint 未保存 `vit_size/vit_layers/multi_scale`。当前 `sample.py` 遇到缺失字段反而默认 448、四层、多尺度，更无法正确加载 v1。
- 复核：使用真实 checkpoint 的解码器键名/形状进行严格加载检查，v1 存在 88 个当前所需但 checkpoint 缺少的键，以及 20 个多余旧键，严格加载失败；v2/v3 解码器结构检查通过。此检查用替身编码器和 meta 张量，不是完整推理测试。
- 修复：恢复明确的 legacy-v1 架构分支，包含旧 `vit_proj`、普通 conv16、普通 DetailCapture；按 checkpoint 结构识别旧版本，更新 sample 与 WSI 入口。**不能用 `strict=False` 跳过新层来冒充 v1 权重加载成功。**

### F04 / P2：验证把通道数当成了图像数

- 位置：`code/vit_matte/train.py:189–195`。
- 每张 tile 向 `psnr_list` 加 16 个通道指标，却用 `len(psnr_list) > 400` 截断，注释写的是约 400 张 tile。
- 小张量实测：batch=4 时只评估 **28** 张；batch=16 时 **32** 张；batch=64 时 **64** 张。验证集实际有 12,402 张。
- 样本集固定为验证集开头且受 batch 大小影响，最佳 checkpoint 和早停判断受很小、可能不具代表性的子集影响。
- 修复：用独立 `n_tiles` 计数，明确固定验证子集或完整验证，保证改变 batch 不改变验证样本范围。

### F05 / P2：单独执行评估时允许测试集缺预测

- 位置：`code/eval/metrics.py:90–118`，`metrics_log.py` 复用同一配对函数；`cell_classify.py:189–223`。
- `align_pairs` 只检查“每个已有预测有没有 GT”，没有检查“split 中每个样本有没有预测”。
- 复现：测试 CSV 有 a、b 两张，预测只放 a，函数仍正常返回 1 对，不报缺 b。
- 细胞评估也会跳过无预测、缺 CSV 或读取失败的 tile；不使用共享特征缓存时尤其容易形成不同模型在不同子集上的比较。
- 外层 `run_full_benchmark.py` 有完整清单检查，可覆盖这一风险，但 README 中直接调用 `eval.metrics*` / `cell_classify` 的命令没有该保护。
- 修复：在指定 split 时校验完整 basename 集合，并报告缺失项；细胞评估保存实际 tile/cell ID 清单。允许子集评估时须显式声明并在结果中标注。

### F06 / P2：默认可视化 tile 名被错误截断

- 位置：共享 `visualize_virtual_stain.py:136,204`。
- 默认 tile 是不带 `.jpeg` 后缀、但中间含 `.ome_...` 的 stem。`os.path.splitext(tile)[0]` 把整个 `.ome_坐标` 当成扩展名去掉。
- 实测默认输入 `18459_LSP10364_US_SCAN_OR_001__092347-registered.ome_0_27648_0_512_512` 被截成 `18459_LSP10364_US_SCAN_OR_001__092347-registered`，预测文件匹配失败，图中可能只剩 HE/GT。
- 修复：仅移除已知真实扩展名 `.jpeg/.jpg/.png/.tif/.tiff`；优先直接使用匹配到的 CSV 行的 H&E basename。

### F07 / P2：best.pt 的保存被早停 min_delta 绑住

- 位置：`code/vit_matte/train.py:436–453`，根目录缺失依赖的实际实现 `datacore/training_monitor.py:29–43`。
- `stopper.update()` 的 improved 指“超过 best + min_delta”，训练把这个值直接用于是否保存 best.pt。
- 实测 30.00 → 30.01，默认 min_delta=0.02 时第二次不保存；因此 best.pt 不是严格的最高 PSNR checkpoint。
- 修复：保存 best 用 `psnr > best_psnr`；早停另用 min_delta 判断是否显著改善。
- 这是当前后加早停代码的问题，不据此否定历史 v3 的 step17000 best；历史日志与 checkpoint 确认其 best_psnr=31.1258。

### F08 / P2：旧 checkpoint 续训会丢失“历史最佳”基准

- 位置：`code/vit_matte/train.py:354–367,436–453`。
- 实际 v3 checkpoint 有 `best_psnr=31.1258`，但没有 `early_stopper`。恢复时变量 best_psnr 被读回，stopper.best 却仍为 None。
- 下一次验证即使只有 20，stopper 仍认为 improved=True，训练会覆盖 best_psnr 并保存更差的 best.pt。已复核缺少 stopper 状态时的实际更新行为。
- 修复：缺少 stopper 状态但存在有限 best_psnr 时，用历史 best 初始化 stopper，同时按 F07 分离最佳模型保存。
- 此外单卡 shuffle 的 RNG/sampler 状态未入 checkpoint，跳过已处理 batch 并不保证继续同一随机顺序；这属于精确续训的限制。

### F09 / P2：marker 标准差统计实际只抽取前 N 张

- 位置：`code/vit_matte/compute_marker_stats.py:30–33`。
- `SubsetRandomSampler(range(n))` 只打乱前 n 个索引，而非从整个训练集随机取 n 张。默认只覆盖前 20,000 / 295,096 张。
- split 若按切片排列，会使逐通道 1/σ 权重偏向前几张切片；影响 v1/v2 的统计重建。不能据此推断已有 `marker_std.json` 一定是错误的，原文件的生成历史未完整留存。
- 另一个限制：统计脚本没有 tile_size 参数，默认用 256，而 v1/v2 训练为 512。缩放改变像素分布与标准差，应该固定并记录统计分辨率。
- 修复：固定 seed 后从全体索引抽样，记录抽样清单和分辨率，最好按 slide 分层抽样。

### F10 / P2：逐图 PSNR 遇到完全相同的通道会生成 Infinity

- 位置：`code/eval/metrics.py:75–84,159`；`code/eval/metrics_log.py:68`；训练 evaluate 也直接平均逐图 PSNR。
- 完全相同的全零预测/GT 通道实测返回 `inf`，`np.nanmean` 不会滤掉无穷值；只要一个样本某通道 MSE=0，该通道平均 PSNR 就可能变成无穷，进一步污染总均值和 JSON。
- 这是条件性数值错误，归档指标 JSON 本次检查均为有限值，不能反推历史结果已受此影响。
- 修复：明确零误差策略；需要稳健的全数据 PSNR 时累积每通道 SSE/像素数后再换算，并明确该口径与逐图平均不同。

## 4. 三版真实实验差异

证据优先级：实际 checkpoint 的 config / 参数结构 → 训练日志 → 同期脚本与说明。历史没有保存的实现细节，不能靠现在相同的三份源码倒推为事实。

### 4.1 共同部分

- 任务：H&E 3 通道到 mIF 16 通道回归；剔除原 17 通道中的 PD-1。
- 骨干：Virchow2 ViT-H/14，32 层、维度1280；冻结骨干，Q/V 加 LoRA。
- LoRA：rank=32、alpha=16，缩放 alpha/r=0.5，可训练 LoRA 5,242,880 参数。
- CNN DetailCapture + 上采样/跳连解码；16 个独立 1×1 输出头，Tanh 输出。
- 数据划分记录：train=295,096，val=12,402，test=10,952。
- 优化配置：Adam，lr=2e-4，weight_decay=1e-5，grad_clip=1，warmup=400，计划15 epoch，seed=0，HE 使用 virchow2/ImageNet mean/std。
- 线性/历史 v3 原始训练代码未完整留存；例如 config 中 dropout=0.1，不能据此证明历史实现确有 dropout。

| 统一重评 | 未参加2026-09-20重评 | 名称vitmatte_512 | 名称vitmatte_256 |

**v2与v3的完整模型 state_dict 键名和张量形状完全一致**，但权重值不同，输入空间尺寸、目标归一化、损失及训练设置也不同。这不能简化为“只改了损失”。v3 README 的“ViT-448系架构”只能理解为沿用v2的模块设计，实际运行明确是ViT-224。

ViT token 数v2是v1/v3的4倍；不能直接说总训练成本只增4倍，因为注意力、卷积分支、batch、硬件和数据读取都参与总成本。v3的8.51h对比v2的166.52h也不是单因素加速实验；4卡墙钟、输出分辨率、ViT分辨率、有效batch和GPU共享状况一起变了。v1还没有训练完15epoch，三版耗时不能直接解释为算法效率排名。

### 4.3 目标和损失的精确定义

令 I 为原始0–255强度，c为通道。

- v1/v2：`x_c = 1.8 * I_c / 255 - 0.9`；`w_c = (1/std_c) / mean_c(1/std_c)`；`L = mean_c[w_c * mean_BHW((pred_c - x_c)^2)]`。
- v3：`x_c = 2*log2(min(I_c,q_c)/q_c + 1) - 1`；`w_c=1`；`fg = (x_c > -0.99)`；`L = mean_BCHW[(pred-x)^2 * (1 + 10*fg)]`。
- v3 的fg阈值等价于 `I_c > (2^0.005-1)*q_c ≈ 0.003472*q_c`。它是强度阈值，不是细胞阳性标签；在当前uint8且q≤255的输入下，最小正整数强度1已超过该阈值。
- v3不仅做log变换，还按marker的q重新缩放并截断大于q的尾部强度；模型正常输出最高只能反变换到q，不能恢复被截断的超q峰值。
- log公式及反变换的小张量复核通过，浮点最大绝对误差约3.1e-5。这里的“通过”表示数学实现一致，不代表整套训练和最终评估数值完全一致。
