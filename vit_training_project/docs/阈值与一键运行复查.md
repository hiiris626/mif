# 0.5阈值与一键流程复查

## 结论

0.5是合理的初始决策阈值，不是已经验证最优的阈值。当前16个通道表达分布不同，训练又有平衡采样、MSE＋Dice和通道加权，不能把所有sigmoid输出当作已经充分校准的真实概率。阈值只决定概率如何转成二值标签，不改变训练GT，也不会删除patch。

还要区分两个数字：GT标签目前用“处理后通道强度>0”；本次讨论的0.5则是模型输出概率的阈值。调整预测阈值不会修正GT弱背景噪声。GT像素门控若要改变，必须另开实验，仅用train拟合。

常见二分类工具默认使用0.5，但决策阈值可以针对具体指标在独立验证数据上选择，不能用训练集原地挑选，也不能看test再改阈值。[scikit-learn官方说明](https://scikit-learn.org/1.5/modules/classification_threshold.html)

## 已接入的一键规则

1. **训练期间固定0.5。** 每轮val以相同标准选best、判断早停，避免每轮同时追逐权重和阈值变化。
2. **锁定best。** 模型权重不再更新，用自然分布val的全部有效像素统计各通道概率分布。
3. **独立选16个阈值。** 在约0.05～0.95范围，用256-bin直方图的边界k/256搜索，分辨率1/256，包含精确0.5。候选边界的TP/FP/FN与概率>=该阈值的决策一致。
4. **目标为逐通道像素F1（等价Dice）。** 单通道F1与IoU对相同TP/FP/FN具有单调关系。相同最优值选择最接近0.5的阈值；仍相同时取较低值。
5. **支持不足回退0.5。** 每通道至少100个有效阳性像素、100个有效阴性像素，而且阳性、阴性各来自至少2个验证病例，才进行选择。条件只是防止明显样本不足，不是统计显著性或充分校准的保证。
6. **固定后再看test。** 一次test推理同时累计选定阈值与固定0.5的指标，两份都保留，不能依据test结果再次选阈值。
7. **推理复用同一文件。** thresholds.json绑定checkpoint哈希、数据清单哈希和通道顺序，不能误用其他模型或其他数据的阈值。展示argmax只在已经超过各自阈值的通道里选择。

选择后会输出thresholds.json/csv、验证集阈值曲线、test_metrics.json、test_metrics_default05.json和test_threshold_comparison.csv。这里的“选阈值”不是温度缩放等概率校准，也不改变原始概率NPZ。

val同时参与模型选择与阈值选择，其选择后成绩存在乐观偏差，不能当最终泛化结果。当前只约6个验证病例，像素之间高度相关，因此最终以未参与选择的患者test结果为准，并同时保留0.5基线。

## 本轮修复和检查

- 修复已早停任务在resume时可能再训练一轮的问题。
- 增加逐通道验证阈值选择，并将calibrate阶段接入一键执行顺序。
- 测试、独立推理和可视化使用同一份阈值；GPU预测与评价均采用BF16前向、FP32 sigmoid。
- 修复逐通道阈值下argmax可能选中未达标通道的展示问题。
- 将模型结构配置和运行依赖版本加入续跑一致性检查。
- 容量探测要求四个rank完整返回结果，不能把缺报告误认为普通容量不足。
- 增加一键流程调度测试，以及正式训练循环的四进程CPU端到端测试，覆盖梯度累积、末尾不足一组、早停、续跑、验证阈值、test和最终导出。

CPU端到端测试使用临时合成图像和小卷积替代Virchow2，执行真实的数据加载、训练控制、checkpoint、阈值和报告代码。CUDA、NCCL、SyncBatchNorm以及真实四卡最大batch仍须在审核后验证；本轮没有启动真实数据训练，不能承诺未经执行的GPU路径绝无问题。

审核通过后的统一入口：

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 bash scripts/run.sh --approved --run-dir runs/ddp_baseline
```

不加--approved只查看配置。原始数据、Virchow2权重路径正确、四卡满足空闲显存要求时，入口会依次执行预处理→校验→容量探测→训练→val选阈值→test→最终报告。
