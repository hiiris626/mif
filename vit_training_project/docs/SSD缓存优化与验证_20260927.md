# SSD缓存优化与验证

运行入口仍是 `scripts/run.sh`，运行目录仍是 `runs/ddp_baseline`。2026-09-27 用户授权优化GPU空耗后，旧首轮训练已停止，旧日志、原始代码和容量测试保存在 `runs/ddp_baseline_before_cache_20260927_143247`。旧训练最后记录150步，没有epoch checkpoint；新流程从同一预训练权重重新开始，不将这150步误报为已恢复。

## 已实现

- 流水线增加 `cache` 阶段，完整缓存成功后才启动GPU训练，避免边生成缓存边占着GPU等待。
- 原生333×333的H&E、16通道多标签、组织掩膜、监督有效区域、通道可用性无损打包到当前运行目录所在SSD。约172.7 GiB；构建前检查空间并预留至少15 GiB。数据不做额外筛选。
- 每个patch固定位置存储，包含patch ID和CRC；缓存绑定源清单及统计文件哈希。未完成、错配、截断或损坏的缓存拒绝读取。构建按块保存进度，异常后可继续。
- 训练和验证直接读缓存，免除重复JPEG/TIFF解码及标签生成。源数据仍保留；每轮一张原始GT快照仍需读取一份TIFF。
- 保留原生分辨率标签和增强顺序；缓存前后输出逐像素一致。患者划分、平衡清单、epoch样本数、loss和早停规则不变。
- 标签以uint8传输，0/1/255语义不变；原int64标签的主机内存、进程间传输及GPU拷贝量减少至1/8。loss内部仍用float32计算。
- 数据加载worker持续复用，epoch通过共享变量更新，增强每轮变化；限制各worker的OpenCV/PyTorch线程，避免嵌套线程竞争。
- 日志新增 `max_rank_data_wait_seconds`、`max_rank_model_step_including_sync_seconds`、`native_cache_enabled`。二者是各rank最大累计时间，最大值可能来自不同rank，不可相加当成严格的单卡时间分解；模型阶段也包含DDP同步等待，并非纯GPU算子时间。

## 已运行验证

- 14项单元检查通过：包括缓存前后逐像素一致、缺失通道、全忽略样本、奇数尺寸位打包、8轮增强、persistent worker跨轮更新、损坏/不完整/来源错配缓存拒绝读取。
- 四进程CPU检查通过：全局MSE+Dice/Hinge梯度、空验证rank、全量验证loss、早停、恢复、阈值选择、测试、报告和快照。
- 缓存开启的生产训练流程使用微型模型完成两轮回归检查。
- 真实Virchow2模型、4张GPU、每卡64、真实原始patch缓存，运行12步（3步预热、9步计时），参数更新全部丢弃，不生成正式训练checkpoint。

真实GPU探测：最慢rank平均0.9883秒/步，约259.0 patch/秒，平均取数等待最大约0.00035秒，峰值预留显存每卡41.22 GiB。旧运行第100–150步约5.916秒/步；短测约6倍吞吐差异。**该测试重复使用256个真实patch，属于小型热缓存测试，不代表完整172.7 GiB缓存必然达到相同速度**。全量训练启动后用新增计时项复核。
