# 当前训练 loss 平台分析

分析范围：`runs/ddp_baseline` 已完成的第 1～18 轮；第 19 轮仍在运行。分析只读取训练/验证结果，没有修改正在运行的配置、模型或标签，也没有使用测试集选方案。

## 结论与证据

模型确实学到了信息，问题是验证效果较早进入平台期，而不是 loss 完全不下降。训练 loss 从 0.87547 降到 0.58664（下降约 33.0%），验证 loss 从 0.79262 降到 0.70701（下降约 10.8%）。第 4 轮后，验证 loss 仅从 0.71801 降至 0.70701；当前最佳验证 macro IoU 出现在第 14 轮（0.43929）。第 18 轮 macro IoU 为 0.43674、macro F1 为 0.57003，降低 loss 没有持续转化为更好的分类结果。

当前 loss 是 16 个独立通道的概率 MSE 加逐图逐通道 soft Dice loss，再按训练集正像素强度标准差的倒数加权。它不是单项 MSE，不能把 0.7 当成“70% 的像素预测错误”，也不能与以前强度回归的 loss 直接比较。

| 完成轮次 | train loss | val loss | 验证 MSE | 验证 Dice loss | 验证 macro F1 |
|---|---:|---:|---:|---:|---:|
| 1 | 0.87547 | 0.79262 | 0.08244 | 0.71018 | 0.54924 |
| 4 | 0.61790 | 0.71801 | 0.08910 | 0.62891 | 0.57075 |
| 14 | 0.59092 | 0.70777 | 0.08898 | 0.61879 | 0.57483 |
| 18 | 0.58664 | 0.70701 | 0.08818 | 0.61882 | 0.57003 |

分解方法：已保存的各通道 Brier score 就是该通道有效像素上的概率 MSE；按实际 channel_weights 加权，再从 val loss 中减去即可得到 Dice 部分。两处浮点计算精度略有不同，因此这里是浮点误差范围内的重建。训练日志没有保存训练 MSE/Dice 分项，不能据此声称已经拆出了训练分项。

## 主要问题

### 1. Dice 是主要平台项，两个目标存在取舍

第 18 轮验证 Dice loss 约 0.61882，占总 loss 的 87.5%。从第 4 轮到第 18 轮，它仅下降约 0.01008。第 1 轮到第 18 轮，MSE 反而从 0.08244 上升到 0.08818，而 Dice 大幅改善：当前两项等权优化并没有让每个目标同时改善。

这不是仅凭数值大小就能确定该如何改权重。loss 的数值大小不等于梯度大小；稀疏标签下全预测阴性也能获得较小 MSE。应结合正/负像素分项、各通道召回率、PR/AP 和梯度再比较方案。

### 2. 全阴性通道的 Dice 定义会产生接近常数的惩罚

`vit_seg/distributed.py` 中，只要该图该通道有有效监督像素，就会计算 Dice；并不要求存在阳性标签。对于标签全为 0 的通道：

`DiceLoss = 1 - eps / (sum(probability) + eps)`，其中 `eps = 1e-6`。

假设有 10,000 个有效像素，每个像素预测阳性的概率都只有 0.001，Dice loss 仍约为 0.9999999。该项对概率的导数为 `eps / (sum(probability) + eps)^2`，在这种情况下极小。也就是说，模型已经很确信该通道为阴性，这一 Dice 项却仍接近 1；主要依赖 MSE 继续学习阴性。

按原生分辨率 manifest 统计，排除整块无有效监督的 patch 后，全阴性图像/通道对的加权比例为：自然训练集 10.19%，平衡采样训练清单 17.81%，验证集 7.40%。验证集 FOXP3 为 23.16%，Ki67 为 27.09%。

这是明确的目标函数设计问题，但不能解释全部平台：验证集受影响的图像/通道对约 7.4%，而 Dice loss 约 0.619。这里的比例还没有经过缩放和增强，不是每轮实际 Dice 常数项，也不是不可突破的数学下界。

### 3. 部分通道确实学得弱，patch 平衡没有消除像素不平衡

| 通道 | 验证监督像素中阳性比例 | F1 | Recall |
|---|---:|---:|---:|
| Hoechst | 71.45% | 0.925 | 0.945 |
| ECadherin | 25.21% | 0.871 | 0.922 |
| FOXP3 | 1.55% | 0.174 | 0.161 |
| PDL1 | 16.73% | 0.202 | 0.124 |
| CD8a | 6.75% | 0.306 | 0.278 |
| CD163 | 8.99% | 0.346 | 0.329 |

这些比例仅针对实际参与监督的像素，不能解读为整张组织的表达率。PDL1 并不极度稀少，效果仍弱，说明不能用“阳性少”解释所有通道的问题；还需区分标签定义、患者差异和 H&E 中可预测的信息。

各通道的 false:true1:true2 平衡清单合并后，同一 patch 的所有有效通道共同接受监督，因此最终每个通道不会保持严格 1:1。更关键的是，阳性 patch 中也可能只有很少阳性像素。现在的通道权重约 0.86～1.10，来源于阳性强度标准差；它并不补偿二值标签的正负像素比例。

### 4. 泛化收益趋于饱和，但不能仅凭 loss 差值断言过拟合

训练 loss 缓慢降低，验证指标从第 4 轮起总体波动较小，说明继续训练的泛化收益已明显减弱。但训练采用平衡重采样和增强，验证使用自然分布；训练值是随模型更新的 batch loss 均值，验证值是固定模型的全量统计。二者并非同分布、同汇总方式，0.12 左右的差距不能全部归因于过拟合。

### 5. 标签阈值需复核，预测阈值 0.5 不是 loss 平台的原因

当前 GT 标签仍定义为处理后的 mIF 强度 `>0`。它把非零值视为阳性，是否包含弱背景或配准边缘噪声，需要原始图、处理后 GT 与标签的抽查才能判断；本次没有证据把它确认为主因。如果复核标签阈值，应仅用训练集拟合，保留未知通道忽略监督及 DAPI 仅作质控的既定规则。

预测阈值 0.5 只参与分类指标和二值展示；训练 MSE 和 Dice 直接使用 sigmoid 概率。调整 0.5 可以改变 Precision/Recall/F1，但不会改变当前训练 loss。现有流程已安排在训练结束后用验证集校准各通道阈值，测试集不参与选择。

## 下一步优先级

1. 保留这次运行作为基线。新增实验先补充训练/验证 MSE、阳性样本 Dice、空目标 Dice、每通道正负像素比例和 Recall 的分项记录。
2. 首先对照“Dice 只在有阳性标签的图像/通道对计算，所有有效正负像素继续由 MSE 监督”。不能把阴性样本整体丢掉。修改后 loss 的绝对值会自然变化，应在相同患者划分和验证指标上比较，不能以 loss 数字变小宣布改进。
3. 再单独比较保留 MSE 的方案与 BCEWithLogits + 正样本 Dice。若加入正类权重，应使用训练集比例并限制范围，观察 Recall 提升是否以大量假阳性为代价。当前证据不足以直接确定最优权重，也不能保证替换为 Lovasz-Hinge 会更好。
4. 优先抽查 FOXP3、PDL1、CD8a、CD163 的 GT 和预测，并按验证患者拆开指标。先确认标签和患者差异，再考虑改变分辨率、融合结构或 LoRA 范围，避免一次改多项无法归因。

训练仍正常推进，最近吞吐约 258 patch/s；第 18 轮 LoRA 学习率约 6.42e-5，decoder 约 1.92e-4，并未接近余弦退火最低值。当前证据不支持把平台归咎于 GPU 空耗或学习率已经降到近零。本次没有中途修改训练目标。
