# MIPHEI流程复核与本项目采用方式

> 当前执行：直接复用已质控发布patch，不再运行StarDist或二次清洗；保留DAPI阴性、其他通道有信号的patch。下文核质控等级仅为历史方案，不在主流程执行。

## MIPHEI实际做法

MIPHEI没有用一个DAPI Dice阈值决定全部marker样本是否保留。作者将问题拆成几类：

1. 对mIF做自荧光扣除并按通道归一化；用空抗体通道发现影响全部mIF通道的伪影。
2. 用H&E基础模型特征聚类发现明显H&E伪影。
3. 人工标注部分错配tile，再训练H&E+DAPI的CNN检测错配；论文报告综合过滤约4万张tile，约占10%。
4. 在DAPI上用微调Cellpose分割细胞核，扩张2μm作为细胞区域近似。
5. 在每个细胞区域计算marker平均强度，用GMM区分阳性/阴性，再按生物学层级修正伪标签，例如CD3阳性需要同时满足CD45阳性。
6. 图像模型仍直接学习对齐mIF；细胞分割和伪标签主要用于细胞级评价，不把核区域当作所有marker的像素有效区。

来源：[MIPHEI论文数据预处理](https://arxiv.org/html/2505.10294v1#S3.SS4)、[官方预处理说明](https://github.com/Sanofi-Public/MIPHEI-ViT/blob/main/preprocessings/README.md)。

## 本地318,450张patch是否已经质控

是。当前目录是MIPHEI在Zenodo发布的最终预处理版，不是作者质控前的原始候选tile：

- `train/val/test_dataframe.csv`共295,096/12,402/10,952张，合计318,450张、41张WSI；
- 三个split清单和`slide_dataframe.csv`与本地官方zip中的文件逐字节哈希一致；
- zip只包含最终四张dataframe、H&E/mIF/nuclei patch及逐细胞CSV，没有`clean_tile_dataframe`之前的候选清单、被剔除tile清单或逐patch QC原因；
- split表已带每通道的`*_prop`和`*_count`字段，说明它位于核分割、单细胞表达提取/门控之后；
- 官方预处理顺序是从`clean_tile_dataframe.csv`提取最终tile，论文明确报告此前约过滤4万张、约10%的ORION tile。

因此不能把318,450张再称为“原始未清洗数据”，也不能仅凭当前发布包精确还原哪4万张被删除、每张因何删除。此前新增的StarDist诊断审计已按用户最新决定取消；历史预览不能冒充MIPHEI原始质控复现，也不应按核Dice删除整张patch。

## 值得借鉴的部分

| MIPHEI做法 | 本项目采用方式 | 原因 |
|---|---|---|
| 将伪影、H&E质量、错配分开处理 | 输出独立QC字段，不把核Dice当总质量分数 | 不同失败原因需要不同处置 |
| DAPI承担核定位和细胞级分析 | DAPI核一致性仅作质控；DAPI阴性但其他通道阳性的patch保留 | 避免删除核外marker监督 |
| 按通道处理mIF | 每个patch×通道保存valid标记；无效通道loss和指标为ignore | 缺失不是生物学阴性 |
| 使用病例/切片分组 | 固定病例29/6/6，所有统计只在train拟合 | 防止同病例泄漏 |
| 单细胞GMM与层级规则 | 作为后续细胞级伪标签/评价分支，不替代逐像素多标签 | 像素表达与细胞类型是不同任务 |
| 细胞级指标 | 后续在细胞实例上补充per-marker F1/AUPRC | 像素指标不能完全说明表型是否恢复 |

## 不直接照搬的部分

- 本地`nuclei`文件是DAPI Cellpose后扩张的细胞区域代理，适合细胞强度汇总，不能直接与H&E StarDist纯核做同定义Dice。
- MIPHEI的GMM阈值是细胞级伪标签，不等于像素`>0`标签。若引入，应作为独立实验并保存每通道阈值、后验概率和层级规则。
- 原作者用于错配检测的人工标注和CNN权重当前不在本地数据包中，不能宣称已复现该过滤器。
- 空抗体通道不在当前16通道训练目标中，无法原样复现作者的全通道伪影检测。
- 核扩张2μm只是细胞质近似，膜性、基质和胞外marker不能被强制限制在该区域。

## 历史核质控方案（当前不执行）与通道处理规则

每张可读且配对完整的patch保留。DAPI/Hoechst核质控状态分为：

- `gold`：可评价且Dice>0.6；
- `retained`：可评价且0.2≤Dice≤0.6；
- `rejected`：可评价且Dice<0.2，但这里只表示核质控失败，patch仍保留；
- `not_evaluable`：DAPI全零、参考核过少或H&E StarDist核过少，进入复核清单，patch仍保留。

`rejected`为兼容原阈值的核质控等级，不代表数据删除。最终清单同时写入`patch_retained=true`和保留理由。

通道级处理规则：

- 文件包含该通道，且同一切片至少一个patch出现该通道信号，视为已观测通道；当前patch为零时才可进入该通道false候选。
- 同一切片该通道全部无信号，记为可用性未知，暂忽略该通道监督和评价；不能据此判定缺失或染色失败，其他通道仍可使用。
- DAPI阴性但其他通道阳性的patch保留。DAPI可作为有效负例或核质控不可评价项，但不遮罩其他通道。
- 所有通道都为零的组织像素从当前多标签loss排除；它不自动导致整张patch删除。

进一步提高“可信阴性”的可靠性，需要补充MIPHEI式伪影检测、上游采集元数据或人工复核。仅凭像素为零无法区分真实阴性、染色失败和处理后被清零。
